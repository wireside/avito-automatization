## Как читать

- `x-contract-level: source-documentation` — документация метода перенесена, но строгой машинной схемы нет. Пустая схема `{}` означает **неизвестную форму**, а не разрешение любого тела сервером.
- `x-contract-level: typed-subset` — дополнительно описана часть полей/ограничений. Не означает полной схемы всех отраслей, всех ответов и условных обязательностей.
- `x-source` — исходник, страницы PDF, раздел и страница объявления URL. У длинного текста полный оригинал доступен по ссылке; сокращение описания явно помечено.
- `x-document-payloads` — разделы JSON-документов True API; не отдельные HTTP endpoints. Их исходные таблицы включены в описание общей подачи.
- `x-side-effects` — предупреждение о побочных эффектах; не формальное разрешение вызова. В том числе GET генерации GTIN, отправки на модерацию, выдачи новых КМ небезопасен для автоматической пробы.
- `x-live-verified: false` — восстановление из PDF само по себе не является проверкой метода на аккаунте.
- `x-codegen-ready: false` — нельзя автоматически получить production-клиент/валидатор всего API без доработки и проверки контрактов.

Схемы intentionally permissive: дополнительные поля сохраняются для исследования, условные юридические требования читать в источнике. Не подключать эти файлы как полную runtime-валидацию склада.

## Просмотр без выполнения запросов

JSON соответствует OpenAPI **3.0.3** и открывается Swagger UI / редактором с поддержкой OpenAPI. Не загружать API Key и реальные КИ в публичный Swagger Editor. Для локального просмотра можно запустить Swagger UI с запросами и внешней валидацией, отключёнными явно:

```sh
docker run --rm -p 127.0.0.1:8080:8080 \
  -e SWAGGER_JSON=/reference/docs/openapi/chz/national-catalog-api.openapi.json \
  -e SUPPORTED_SUBMIT_METHODS='[]' \
  -e VALIDATOR_URL=none \
  -v "$PWD/docs:/reference/docs:ro" \
  -v "$PWD/docs:/usr/share/nginx/html/docs:ro" \
  docker.swagger.io/swaggerapi/swagger-ui
```

В браузере открыть `http://127.0.0.1:8080`. Для другого справочника поменять имя в `SWAGGER_JSON`. Ссылки на источники ведут в `/docs/chz/sources/`; при просмотре в другом инструменте открыть соответствующий локальный PDF из проекта. Команда приведена для ручного просмотра, автоматически контейнер не запускается. Параметры проверены по официальным [инструкции Docker](https://github.com/swagger-api/swagger-ui/blob/master/docs/usage/installation.md#docker) и [настройкам Swagger UI](https://github.com/swagger-api/swagger-ui/blob/master/docs/usage/configuration.md#network).

Первый сервер намеренно `https://example.invalid`. Выбор sandbox/production — отдельное осознанное действие. API Key НК и токен True API альтернативны, не передаются совместно; секреты остаются на backend. Подписи, эмиссия, модерация, создание выгрузок и документы не запускаются при проверке документации.

## Воспроизведение и проверка

Скрипты не используют `.env` и не обращаются к ЧЗ. Их Python-зависимости — только во временном окружении, не в runtime проекта:

```sh
python3 -m venv /tmp/chz-docs-check
/tmp/chz-docs-check/bin/pip install pypdf==6.10.0 openapi-spec-validator==0.7.2
/tmp/chz-docs-check/bin/python docs/openapi/chz/rebuild.py /path/API_CHZ.zip /tmp/chz-rebuilt
/tmp/chz-docs-check/bin/python docs/openapi/chz/check.py . --archive /path/API_CHZ.zip
```

`rebuild.py` принимает только SHA-256 разобранной версии архива. Изменившийся архив требует пересмотра сопоставления PDF и контрактов, а не молчаливой перегенерации. Результат сначала собирать вне рабочего дерева, затем сравнивать и переносить после review. Скрипт извлечения детерминирован по содержимому PDF и версии pypdf; история генерации не является подтверждением актуальности сервера.

`check.py` проверяет OpenAPI стандартным валидатором, операции и provenance по coverage, параметры путей, уникальность operationId, SHA-256 исходников, страницы, ссылки документации и наличие всех страниц в индексе. С `--archive` дополнительно проверяется соответствие всем шести PDF в исходном ZIP. Он не проверяет настоящую авторизацию, квоты, УКЭП, СУЗ, ЭДО или юридическое состояние.
